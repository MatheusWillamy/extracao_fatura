Especificação Completa: API e Regras de Extração de Faturas

Documentação fiel à implementação real em main.py e extractor.py: rotas HTTP, regras de sinal (positivo vs. negativo), micro-análises de dia, mês, ano, fuso e números, além de exemplos práticos do que o motor cobre e do que não cobre.

1. Endpoints e Formas de Envio da API

Método Rota Função Observações
GET / Status e lista de rotas Retorna version: "1.1.0" e mapa de endpoints
GET /health Healthcheck Usado pelo Docker/Easypanel ({"status": "ok"})
POST /extract Extração principal Aceita multipart, binário bruto ou JSON Base64
POST /homo_extracao_enel Webhook compatível n8n Mesmo handler de /extract
POST /webhook Webhook genérico Mesmo handler de /extract

Prioridade de leitura do PDF (_get_pdf_bytes_from_request)

1. Multipart (file || data || attachment)
→
2. Binário application/pdf / octet-stream
→
3. JSON Base64 (file_base64/data/file/content)
→
4. Assinatura inicial %PDF

O que a entrada da API COBRE

  • Upload multipart nos campos file, data ou attachment.
  • Body binário puro com Content-Type: application/pdf ou application/octet-stream.
  • JSON com Base64 puro ou com prefixo Data URI (data:application/pdf;base64,...).
  • CORS aberto (*) para chamadas web (ex.: FlutterFlow Web).

O que a entrada da API NÃO COBRE

  • Campos multipart com outros nomes (ex.: pdf, arquivo, documento) → erro HTTP 400.
  • JSON enviando apenas URL externa para download do PDF.
  • Upload múltiplo/em lote em uma única requisição.
  • Imagens (PNG/JPG) ou PDFs escaneados sem texto vetorial (sem OCR).

2. Modos de Extração, Wrapper e Compatibilidade

Parâmetro Onde enviar Padrão Comportamento exato
mode Query ou JSON Body "auto" structured: só parser Python.
ai: envia pdf_text[:12000] para Gemini/OpenRouter/OpenAI.
auto: roda Python; só faz fallback de IA se (total_a_pagar == 0.0 e lista_itens_fatura == []) ou se ocorrer exceção, exigindo chave em x-api-key, GEMINI_API_KEY ou OPENROUTER_API_KEY.
wrap_output Query ou JSON Body true Quando true, retorna todos os campos na raiz e dentro de "output": { ... } (padrão do nó Information Extractor do n8n).
x-api-key Header HTTP None Sobrescreve variáveis de ambiente para chamadas de IA.
Micro-detalhes importantes de comportamento: (1) No modo auto, configurar apenas OPENAI_API_KEY não aciona fallback automático (o cheque de fallback testa só api_key, GEMINI_API_KEY e OPENROUTER_API_KEY); use mode=ai ou passe em x-api-key. (2) No modo ai, apenas os primeiros 12.000 caracteres do texto extraído via pypdf são enviados (não envia PDF como imagem). (3) format_api_response sempre garante o alias "cnpj_cpf" além de "cnpj-cpf".

3. Micro-Análises Globais: Números e Regras de Sinal

Função _clean_number(val_str)

"3.214,70-"
→
detecta '-' no início ou fim (is_neg=True)
→
remove '-' e '.' (milhar) → "3214,70"
→
troca ',' por '.' → "3214.70"
→
-3214.7 (se 0 retorna 0.0)

O que _clean_number COBRE

  • Sinal à direita (padrão Enel): "142,88-" → -142.88
  • Sinal à esquerda: "-142,88" → -142.88
  • Milhar com ponto: "2.594,60" → 2594.6
  • Zero negativo: "0,00-" → 0.0 (evita -0.0)

O que _clean_number NÃO COBRE

  • Número no formato US ("142.88" vira 14288.0 porque . é removido como milhar).
  • Espaço entre sinal e número (ex.: "- 142,88").
  • Moeda ou texto junto ao número (ex.: "R$ 142,88").

Matriz de Sinais (Positivo vs. Negativo) por Campo

Campo Regra de Sinal Exemplo Positivo Exemplo Negativo
lista_itens_fatura[*].valor Preserva + e - 2594.6 + valor_positivo: true -142.88 + valor_positivo: false

4. Regras Detalhadas de Cada Campo

Nenhum campo corresponde ao filtro/busca atual.
creditos_utlizados (grafia sem 2º "i")
List[Dict] Sempre >= 0

Regex: r"Saldo utilizado no m[eê]s:\s*([0-9.,]+)\s*([a-zA-Z]+)" (case-insensitive). Fallback: [{"quantidade": 0, "unidade": "kWh"}].

Micro-análise de pontuação (milhar x decimal)

Divide por ponto: parts = qtd_str.split('.').

"1.000.00" (3 partes)
→
junta antes do último ponto → "1000.00"
→
is_integer() → int 1000
"1.660.20" (3 partes)
→
"1660.20"
→
round(1660.2, 2) → float 1660.2
"453.26" (2 partes)
→
mantém "453.26"
→
float 453.26

Exemplos que COBRE

  • Saldo utilizado no mês: 453.26 kWh → 453.26, "kWh"
  • Saldo utilizado no mês: 1.000.00 kWh → 1000 (int)
  • Saldo utilizado no mes: 7.140.00 kWh → 7140 (int)
  • Saldo utilizado no mês: 7140,50 kWh → 7140.5

Exemplos que NÃO COBRE

  • 1.000,50 kWh (1 ponto de milhar + vírgula): entra no ramo de 2 partes e falha no float("1.000,50"), virando 0!
  • 1.000 kWh (1 ponto de milhar sem decimais): vira 1 (1.0) em vez de 1000!
  • Rótulos diferentes (ex.: "Crédito utilizado:") ou valores negativos.
creditos_valor
float Soma com sinal (-)

Regra: round(sum(energia_atv_inj_TE_valor) + sum(energia_atv_inj_TUSD_valor), 2). Preserva o sinal negativo dos créditos de injeção abatidos.

Exemplos que COBRE

  • 1 mês (TE -145.86 + TUSD -158.76) → -304.62.
  • Múltiplos meses (10/2024 + 11/2024: -142.88 - 2440.85 - 188.19 - 3214.70) → -5986.62.
  • Fatura sem injeção → 0.0.

Exemplos que NÃO COBRE

  • Compensação de bandeira (Adic. Band. ... Comp.) não entra nesta soma.
  • Créditos sem a expressão literal Energia Atv Inj TE oUC ou TUSD oUC + data MM/AAAA + unidade kWh.
energia_atv_inj_TE_valor & energia_atv_inj_TUSD_valor
List[{"mes": int, "ano": int, "valor": float}] Preserva sinal (-) MM/AAAA → int

Micro-análise para formar Mês, Ano e Valor

1. A linha deve casar com a regex kWh na tabela de itens.

2. Verifica substring exata (case-sensitive): "Energia Atv Inj TE oUC" ou "Energia Atv Inj TUSD oUC".

3. Extrai data no nome do item com r"(\d{2})/(\d{4})" e converte para inteiros.

"Energia Atv Inj TE oUC 08/2025 mPT GD2 ... 145,86-"
→
mes: int("08") = 8
→
ano: int("2025") = 2025
→
valor: -145.86

Exemplos que COBRE

  • Múltiplas competências na mesma fatura (ex.: 10/2024 e 11/2024).
  • Sufixos variados após a data: mPT, mPT GD2, GD1.
  • Sinal à direita (142,88-) ou à esquerda (-142,88).

Exemplos que NÃO COBRE

  • Ano de 2 dígitos (08/25) ou mês de 1 dígito (8/2025).
  • Caixa diferente (ENERGIA ATV INJ TE OUC falha no teste case-sensitive).
  • Outras modalidades como mUC / aUC sem oUC, ou unidade diferente de kWh.
bandeira
str

Ordem de prioridade (4 níveis)

  1. Cor extraída do item na tabela (Adic. Band. <Cor> Comp. ou Adicional Band. <Cor>).
  2. Regex global: r"Band(?:eira)?\.?\s*Tarif\.?:\s*([A-Za-z]+)".
  3. Regex global: r"Bandeira\s+([A-Za-z]+)".
  4. Busca de substring no texto minúsculo (amarela → vermelha → verde), senão padrão "Verde".

Exemplos que COBRE

  • Adic. Band. Amarela Comp. → "Amarela".
  • Períodos: Band. Tarif.: Vermelha : 04/07 - 04/08 → "Vermelha".
  • Fatura sem menção adicional → "Verde".

Exemplos que NÃO COBRE

  • Patamar (não diferencia "Vermelha" patamar 1 de patamar 2).
  • Bandeira de duas palavras (ex.: "Escassez Hídrica" capturaria só a primeira palavra).
bandeira_valor & bandeira_dados
float/int & Dict bandeira_valor: abs (>=0) bandeira_dados: comp (-) / adic (+)

bandeira_valor: retorna abs(adic_band_comp_val) se adic_band_comp_val != 0.0, senão 0.
bandeira_dados: {"adic_band_comp": float, "adicional_band": float} preservando o sinal de cada item da tabela.

Exemplos que COBRE

  • Com compensação e adicional (29,07- e 34,37): bandeira_valor: 29.07, adic_band_comp: -29.07, adicional_band: 34.37.
  • Bandeira Verde: bandeira_valor: 0, ambos 0.0 em bandeira_dados.

Exemplos que NÃO COBRE

  • Fatura sem compensação GD que tenha apenas Adicional Band. Amarela 20,71 (sem Comp.): adicional_band fica 20.71, mas bandeira_valor fica 0.
  • Múltiplas linhas de bandeira de meses distintos (sobrescreve com a última, não soma).
data_vencimento
str (AAAA-MM-DD) Micro-análise Dia/Mês/Ano

Micro-análise de formação Dia, Mês e Ano

1ª tentativa (boleto): r"Data Vencimento:\s*(\d{2})/(\d{2})/(\d{4})" (aceita quebra de linha com \s*).

2ª tentativa (cabeçalho): r"\d{2}/\d{4}\s+(\d{2})/(\d{2})/(\d{4})\s+R\$\s*[0-9.,]+" (ex.: 08/2025 14/08/2025 R$ 265,29).

"14/08/2025" → d="14", m="08", y="2025"
→
f"{y}-{m}-{d}"
→
"2025-08-14"

Exemplos que COBRE

  • Data Vencimento:\n14/08/2025 → "2025-08-14"
  • 08/2025 14/08/2025 R$ 265,29 → "2025-08-14"

Exemplos que NÃO COBRE

  • Rótulo "Vencimento: 14/08/2025" (sem "Data") se não houver a linha do cabeçalho com R$.
  • Ano com 2 dígitos (14/08/25) ou mês por extenso.
subtotal & total_a_pagar
float Sempre abs (>= 0)

subtotal: soma todas as linhas que casam r"Subtotal\s+[A-Za-zÀ-ÿ]+\s+([0-9.,]+)" com abs(...). Se resultar em 0.0, usa total_a_pagar.
total_a_pagar: 1º tenta r"Valor do Documento:\s*R\$\s*([0-9.,]+)"; 2º tenta r"\bTOTAL\s*\n\s*([0-9.,]+)" (com abs(...)).

Exemplos que COBRE

  • Subtotal Faturamento 879,46 + Subtotal Outros 339,57 → subtotal: 1219.03.
  • Valor do Documento: R$ 265,29 → total_a_pagar: 265.29.

Exemplos que NÃO COBRE

  • Subtotal de Serviços 50,00 (mais de 1 palavra após Subtotal).
  • Fatura sem Valor do Documento: R$ ... onde o total aparece na mesma linha ou acima da palavra TOTAL.
  • Valores negativos em subtotal ou total_a_pagar (abs sempre positivará).
leitura_anterior, leitura_atual & tipo_ligacao_eletrica
str (ISO-8601) & str Micro-análise Dia/Mês/Ano/Fuso

Regex conjunta obrigatória para os 3 campos

r"(TRIF[AÁ]SICO|MONOF[AÁ]SICO|BIF[AÁ]SICO)\s+(\d{2})/(\d{2})/(\d{4})\s+(\d{2})/(\d{2})/(\d{4})"
"Residencial TRIFÁSICO 03/07/2025 04/08/2025 32 03/09/2025"
→
tipo: "TRIFÁSICO"
leitura_anterior: "2025-07-03T00:00:00-03:00"
leitura_atual: "2025-08-04T00:00:00-03:00"

Hora T00:00:00 e fuso -03:00 são fixos; a 3ª data (próxima leitura 03/09/2025) é ignorada.

Exemplos que COBRE

  • TRIFÁSICO, MONOFÁSICO, BIFÁSICO (com ou sem acento, convertidos com .upper()).
  • Datas com quebra de espaço/linha entre si.

Exemplos que NÃO COBRE

  • Se o tipo de ligação não estiver colado imediatamente antes das duas datas, os 3 campos ficam "" (não há fallback pela tabela de medidores).
  • Tipos compostos como "BIFÁSICO 2 FIOS" ou fusos diferentes de -03:00.
cnpj-cpf (+ alias automático cnpj_cpf)
Dict[bool, str]

Regex: r"CPF/CNPJ:\s*([0-9.\-\/]+)". Primeiro busca dentro do bloco cadastral (até 6 linhas após a âncora de leitura); se ausente, busca no texto completo. Conta apenas dígitos (\D removido): 11 dígitos = CPF; 14 dígitos = CNPJ; campo não usado recebe literalmente a string "undefined".

Exemplos que COBRE

  • CPF/CNPJ: 105.432.952-49 → cpf: true, cnpj: false, cpf_valor: "105.432.952-49", cnpj_valor: "undefined".
  • CPF/CNPJ: 07.140.525/0001-71 → cnpj: true, cnpj_valor: "07.140.525/0001-71", cpf_valor: "undefined".
  • Documento sem máscara com 11 ou 14 dígitos (ex.: 10543295249).

Exemplos que NÃO COBRE

  • CPF/CNPJ mascarado com asteriscos/letras (ex.: ***.432.952-** → menos de 11 dígitos → ambos "undefined").
  • Rótulo apenas CNPJ: ou apenas CPF: (protege contra pegar o CNPJ da Enel no cabeçalho).
endereco
{"nome da empresa", "endereço", "cep"}

Micro-análise: Localiza a linha âncora (TRIF[AÁ]SICO|MONOF[AÁ]SICO|BIF[AÁ]SICO)\s+\d{2}/\d{2}/\d{4}. A linha seguinte vira nome da empresa; as linhas de +2 a +7 até CPF/CNPJ: (pulando a linha de CEP:) são unidas em endereço. Se o CEP não estiver no bloco, o fallback busca CEP:\s*(\d{5}-\d{3}) no texto inteiro descartando "60135-040" (sede Enel Ceará).

Exemplos que COBRE

  • Bloco padrão Enel CE com até 5 linhas entre nome e CPF/CNPJ:.
  • CEP no formato XXXXX-XXX, diferenciando do CEP da Enel CE (60135-040).

Exemplos que NÃO COBRE

  • Razão social quebrada em 2 linhas (a 2ª linha entra em "endereço").
  • CEP sem hífen (60150190) ou concessionária de outro estado no fallback (só exclui 60135-040).
  • Ausência da linha âncora de tipo de fornecimento deixa nome da empresa e endereço como "".
CIP_ILUM_PUB_PREF_MUNICIPAL, juros_valor & multa_valor
float Tabela preserva sinal / Fallback abs

Na tabela (raw_item_lines):
• r"CIP ILUM PUB PREF MUNICIPAL\s+(-?[0-9.,]+-?)"
• r"Juros Morat[oó]rios\s+(-?[0-9.,]+-?)"
• r"^Multa\s+(-?[0-9.,]+-?)"
Se permanecer 0.0, faz fallback no texto completo com abs(...) (usando \bMulta\s+([0-9.,]+)).

Exemplos que COBRE

  • CIP ILUM PUB PREF MUNICIPAL 65,09 → 65.09 (e 10,50- na tabela → -10.5).
  • Juros Moratórios 0,45 → 0.45 (aceita com ou sem acento em Moratórios).
  • Multa 6,70 no início da linha → 6.7.

Exemplos que NÃO COBRE

  • Nomes diferentes: COSIP, Contribuição Ilum. Pública, Juros de Mora, Multa Moratória.
  • Texto entre rótulo e valor (ex.: Multa Ref. 04/2025 6,70).
lista_itens_fatura
List[{"nome_item": str, "valor": float, "valor_positivo": bool}] Positivo (true) & Negativo (false)

Regra definitiva de Sinal + Janela da Tabela

Invariante: valor < 0 → valor negativo e valor_positivo: false. valor >= 0 → valor positivo (ou 0.0) e valor_positivo: true.

Janela: linhas entre "itens de fatura" e "subtotal faturamento" (case-insensitive), ignorando linhas de cabeçalho que contenham "com tributos", "valor (r$)", "pis/cofins", "base calc", "icms", "alíquota", "tarifa" ou "unit (r$)". 

r"^(.*?)\s+kWh\s+(-?[0-9.,]+-?)\s+(-?[0-9.,]+-?)\s+(-?[0-9.,]+-?)"
"Energia Atv Inj TE oUC 10/2024 mPT kWh 394 0,36181- 142,88- ..."
→
valor: -142.88
valor_positivo: false

Exemplos que COBRE

  • Todos os itens de energia com unidade kWh (consumo, fornecida, injetada TE/TUSD, adicionais e compensações de bandeira).
  • CIP ILUM PUB PREF MUNICIPAL, Juros Moratórios e Multa dentro da janela.
  • Valores negativos à direita (142,88- → -142.88 / false) ou à esquerda (-50,00 → -50.0 / false).
  • Soma dos itens fecha com total_a_pagar em faturas padrão (265.29 e 1219.03).

Exemplos que NÃO COBRE

  • Lançamentos sem kWh que não sejam CIP/Juros/Multa — ex. real: DOACAO ART CIDADA JUAZEIRO 85 99191 1643 2,00.
  • Unidades diferentes de kWh (ex.: kW, kVArh), parcelamentos, taxas de religação e serviços de terceiros.
  • Itens listados após Subtotal Faturamento.
  • Itens cujo nome contenha palavra do filtro de cabeçalho (ex.: "tarifa", "icms") ou nome quebrado em 2 linhas antes de kWh.
